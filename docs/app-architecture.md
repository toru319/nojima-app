# 家電提案アシストPad アプリ構成設計書

作成日: 2026-07-04

## 目的

iPad Safariで店頭接客中に使える、静的な家電提案補助Webアプリを作る。ヒアリング回答をタグ化し、登録済み商品データから候補を提示、最大3商品を比較、JANコードで商品検索できるようにする。

## 前提

- GitHub Pagesで公開できる静的Webアプリにする。
- サーバー、外部API、Google Apps Script、npm、Vite、React、Vueは使わない。
- Tailwind CSS CDN、HTML、JavaScript、localStorageだけで動かす。
- 商品データは `data.js` の `products` 配列に直接登録する。
- 顧客個人情報、リアルタイム価格、在庫、社内情報は扱わない。

## 画面構成

1. ホーム
   - アプリタイトル、説明、部門別カテゴリカード、JAN検索ボタン、比較リスト導線を表示する。
2. カテゴリ商品一覧
   - カテゴリ選択直後はヒアリングではなく、登録済み商品の一覧を表示する。
   - 商品名、メーカー、型番、商品タイプ、価格帯、主な特徴を一覧で確認できる。
   - キーワード、メーカー、価格帯、タグで任意に絞り込める。
   - 画面右上と商品一覧近くに、ヒアリングへ進むボタンを置く。
3. ヒアリング
   - カテゴリごとの質問を1問ずつ表示し、進捗バー、戻る、次へ、ホーム導線を固定する。
4. 診断結果
   - 選択タグから商品スコアを計算し、おすすめタイプ、要約、提案コメント、商品カードを表示する。
5. 商品比較
   - 最大3商品を横スクロール可能な表で比較する。
   - 比較リストは個別削除と一括リセットができる。
6. JAN検索
   - 8桁または13桁のJANコードで `products[].jan` を検索する。
7. 未登録JAN
   - JANコピーと商品追加テンプレートコピーを提供する。

## データ設計

`data.js` に以下を置く。

- `categories`: ホームに出すカテゴリ。
- `departments`: 店舗部門とカテゴリのまとまり。
- `questions`: カテゴリIDごとの質問配列。
- `products`: 商品配列。
- `researchNotes`: 調査日・出典・注意事項。

商品は以下の必須項目を持つ。

```js
{
  id: "",
  jan: [],
  category: "",
  maker: "",
  name: "",
  modelNumber: "",
  productType: "",
  priceBand: "",
  tags: [],
  features: [],
  goodFor: "",
  caution: "",
  hearingTips: [],
  comparePoints: [],
  talk: "",
  lastUpdated: ""
}
```

## カテゴリ方針

店舗の売場に合わせ、カテゴリは4部門に分ける。

### 通信

- `smartphone`: スマホ
- `earphone`: イヤホン
- `mobile-battery`: モバイルバッテリー
- `adapter`: アダプター
- `landline-intercom`: 固定電話/インターフォン

### 情報

- `tablet`: タブレット
- `smartwatch`: スマートウォッチ
- `pc`: PC
- `printer`: プリンター
- `router`: ルーター

### 家電

- `hair-dryer`: ドライヤー
- `hair-iron`: ヘアアイロン
- `rice-cooker`: 炊飯器
- `microwave`: レンジ/オーブンレンジ
- `washing-machine`: 洗濯機
- `refrigerator`: 冷蔵庫
- `iron`: アイロン
- `vacuum-cleaner`: 掃除機

### 季節AV

- `air-conditioner`: エアコン
- `tv`: テレビ
- `electric-fan`: 扇風機
- `air-purifier`: 空気清浄機
- `radio`: ラジオ

カテゴリカードは商品数が増えてもホームのスクロール量が増えすぎないよう、小型カードに変更する。カードは部門別にまとめ、視認しやすいアイコンを表示する。

## 商品一覧フィルター

カテゴリをタップしたら `categoryProducts` 画面に遷移する。フィルター状態は画面内だけで管理し、localStorageには保存しない。

フィルター項目:

- キーワード: 商品名、メーカー、型番、特徴、提案トークを対象に検索。
- メーカー: 選択カテゴリ内の商品から自動生成。
- 価格帯: 選択カテゴリ内の商品から自動生成。
- 接客フィルター: 「早く乾かしたい」「重いのが苦手」など、現場の会話に近い日本語ボタンを表示する。内部ではタグ、価格帯、メーカー条件に変換する。

該当商品が0件の場合は、条件変更を促すメッセージを出す。商品登録がないカテゴリでは、商品追加テンプレートとヒアリング導線を案内する。

### 接客フィルター設計

カテゴリごとに `categoryFilterProfiles` を定義する。初期実装では `hair-dryer`、`earphone`、`smartwatch`、`printer` に適用する。

構成:

- `title`: 画面に表示するフィルター名。
- `description`: 使い方の短い説明。
- `groups`: 接客上のまとまり。
- `options`: 画面に出す日本語ボタン。
- `tags` / `priceBands` / `makers`: 内部判定条件。

ドライヤーのグループ:

- お客様の一言
- 髪・頭皮の悩み
- 予算・本体
- 最後に確認したい条件

イヤホンのグループ:

- 使い方
- 音の好み
- 装着感
- 予算・機能

スマートウォッチのグループ:

- 使い方
- 本体・画面
- 機能の深さ
- 予算・電池

プリンターのグループ:

- よく印刷するもの
- インク代・印刷量
- 用紙・機能
- 置き場所・予算

英語タグは内部データとして残すが、商品一覧画面には表示しない。商品カードには、該当する日本語の「接客で使いやすい切り口」を表示する。

## スコアリング

`calculateProductScore(product, selectedTags)` でタグ一致数を返す。将来、タグ重み付けを導入できるよう独立関数にする。

候補抽出は以下の順で行う。

1. 選択カテゴリの商品に限定。
2. 選択タグと商品タグの一致数を計算。
3. スコア1以上を候補にする。
4. スコア降順、同点は商品名昇順。
5. 候補0件の場合は同カテゴリの商品を参考候補として出す。

## localStorage

保存するもの:

- 比較リストの商品IDのみ。

保存しないもの:

- ヒアリング回答。
- 顧客個人情報。
- JAN検索履歴。

## ファイル配置

- `index.html`: UI土台、Tailwind CDN、最小限のカスタムCSS。
- `script.js`: 画面描画、状態管理、検索、比較、コピー処理。
- `data.js`: カテゴリ、質問、商品データ。
- `manifest.json`: PWA風にホーム追加できる最小マニフェスト。
- `README.md`: 公開方法、商品追加方法、注意事項。
- `docs/app-architecture.md`: 本構成設計書。
- `docs/design-spec.md`: デザイン設計書。
- `docs/design-review.md`: 設計レビュー結果。
- `research/dryer-products.md`: ノジマ販売ドライヤー調査。
- `research/earphone-products.md`: イヤホン商品調査。
- `research/smartwatch-products.md`: スマートウォッチ商品調査。
- `research/printer-products.md`: プリンター商品調査。

## GitHub Pages公開

静的ファイルのみなので、GitHubリポジトリ化後に Pages の Source を対象ブランチの root にすれば公開できる。現時点の作業フォルダはGitリポジトリではないため、デプロイにはユーザー側のGitHubリポジトリ作成または連携操作が必要。
