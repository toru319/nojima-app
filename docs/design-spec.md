# 家電提案アシストPad デザイン設計書

作成日: 2026-07-04

## 調査から取り入れること

類似の店頭向けPOS/販売支援UIでは、商品をすばやく選べる大きなグリッド、検索への短い導線、売場スタッフが迷わない明確な次アクションが重要。Shopify POSはタブレット利用、店頭販売、在庫・商品管理を一体で扱う設計を前提にしており、Square Retail POSも小売向けに商品・在庫・販売業務をまとめる構成を打ち出している。

ノジマオンラインのドライヤーカテゴリでは、風量、温風温度、消費電力、マイナスイオン、冷風、スカルプ、海外対応、価格帯、メーカーなどで絞り込める。接客アプリではこの軸を「質問」「比較ポイント」「確認ポイント」に変換する。

イヤホンでは、ノイズキャンセリング、外音取り込み、オープンイヤー、装着感、通話品質、LDAC/空間オーディオ、電池持ち、防水、価格帯を、接客中に押しやすい日本語ボタンへ変換する。

スマートウォッチでは、健康管理、睡眠分析、運動GPS、通知・通話、決済、軽さ、大画面、防水、電池持ちを、お客様の目的から選べる接客ボタンへ変換する。

プリンターでは、写真画質、文書の見やすさ、ランニングコスト、印刷量、A3対応、ADF、FAX、自動両面、設置スペースを、用途から選べる接客ボタンへ変換する。

## レイアウト

- iPad横向きでは部門ごとに小型カテゴリカードを5列前後で並べる。
- iPad縦向きでは2-3列を基本にし、1カードの高さを抑えてスクロール量を減らす。
- カテゴリカードは説明文を短くし、アイコン、カテゴリ名、登録商品数を優先表示する。
- カテゴリ選択後は商品一覧とフィルターを先に表示し、ヒアリングは右上の明確なボタンから開始する。
- 比較表は横スクロールを許可し、セル幅を固定気味にして視線移動を安定させる。
- ヘッダーは濃い青、本文は淡い背景、カードは白で分離する。
- 画面下部に常時固定のナビは置かず、主要操作を各画面の上部と下部に重複配置する。

## タップ設計

- ボタン高は44px以上。
- カードボタンは十分な余白を取り、テキストだけでなくカード全体をタップ対象にする。
- 選択中の回答は青背景と赤アクセント線で明確にする。
- 未選択や比較上限などのエラーはalertではなく画面内メッセージに出す。

## タイポグラフィ

- 本文は16px以上。
- 質問文、商品名、画面タイトルは18-28pxで階層化する。
- ボタン内テキストは折り返し可能にし、横幅不足で潰れないようにする。

## コンポーネント

- 部門パネル: 通信、情報、家電、季節AVごとにカテゴリカードをまとめる。
- カテゴリカード: アイコン、カテゴリ名、登録商品数、短い説明。
- 商品一覧フィルター: キーワード、メーカー、価格帯に加え、接客中に押しやすい日本語の条件ボタンを表示する。
- 接客フィルター: 英語タグではなく「早く乾かしたい」「重いのが苦手」「広がり・パサつきが気になる」「通勤・電車で静かに聴きたい」「耳をふさがない」「睡眠を詳しく見たい」「スマホなしでGPS記録したい」「インク代を抑えたい」「A3も印刷したい」「FAXも必要」などの言葉を使う。
- 質問カード: 進捗、質問、回答選択肢、戻る/次へ。
- 商品カード: 商品名、メーカー、型番、価格帯、特徴、向いている人、注意点、提案トーク。
- 商品一覧カード: 英語タグを出さず、日本語の「接客で使いやすい切り口」をチップ表示する。
- メッセージ: 成功、注意、エラーを色と文言で分ける。
- 比較表: 商品名を先頭行に置き、特徴は最大3つに制限。

## アクセシビリティ

- ボタンは `button` 要素を使う。
- 入力欄には `label` を付ける。
- 進捗バーに `aria-label` を付ける。
- 色だけに依存せず、選択状態はラベル文言と枠線でも示す。

## iPad Safari向け注意

- `100vh` に頼りすぎず、余白とスクロールを自然に許可する。
- `touch-action: manipulation` を指定し、タップ反応を軽くする。
- 横スクロール表は `-webkit-overflow-scrolling: touch` を指定する。
- 文字とボタンが狭い幅で重ならないよう、グリッドは `auto-fit` ではなくTailwindのレスポンシブ列指定を中心にする。
