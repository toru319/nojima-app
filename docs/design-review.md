# 設計レビュー

作成日: 2026-07-04

## チェック結果

- 静的Webアプリ要件: 問題なし。HTML、JavaScript、Tailwind CDN、localStorageだけで実装可能。
- GitHub Pages要件: 問題なし。root直下に主要ファイルを置く構成で公開できる。
- 外部API禁止: 問題なし。商品データは `data.js` に固定する。
- 個人情報禁止: 問題なし。ヒアリング内容は接客条件のみで、保存もしない。
- JAN配列管理: 問題なし。検索処理も配列前提にする。
- 比較最大3件: 問題なし。UIと状態処理の両方で制限する。
- iPad向け: 問題なし。44px以上のボタン、広めカード、横スクロール比較表で対応する。
- 部門カテゴリ追加: 問題なし。商品未登録カテゴリでも商品一覧画面を壊さず表示する。
- 商品一覧フィルター: 問題なし。ブラウザ内 `products` 配列だけで実装できる。
- 比較リストリセット: 問題なし。localStorageの比較ID配列を空にするだけで実装できる。

## 見つかった問題と対応

### 1. カテゴリ構成が店舗部門と合っていない

初期設計は7カテゴリ中心だったが、店舗は通信、情報、家電、季節AVの4部門で運用している。

対応: `departments` を追加し、全カテゴリを部門配下に再編する。既存カテゴリIDは互換性のため維持し、新カテゴリを追加する。

### 2. 実価格を表示しない要件と調査価格の扱い

調査ではノジマオンライン上の税込価格を確認するが、アプリ表示では価格そのものを出さず、低価格帯/中価格帯/高価格帯/プレミアム価格帯に変換する。

対応: `research/dryer-products.md` には調査時点の参考価格を記録し、`data.js` では価格帯のみ使う。

### 3. JAN/型番の正確性

ノジマ商品ページURLや一部ページにJANが載っているが、全商品で公式JAN確認ができるとは限らない。

対応: 確認できたJANは入れる。未確認データを入れる場合はREADMEに実運用前の差し替えを明記する。

### 4. 商品数要件との整合

貼り付け要件には各カテゴリ最低4商品とあるが、今回の追加指示では「基本的には商品はまだ空で大丈夫、ドライヤーデータのみ試しに入力」とある。

対応: 今回はドライヤーを実データ試験投入し、他カテゴリは質問だけを用意する。商品0件カテゴリでも壊れず参考候補なしの案内を出す。

### 5. カテゴリカードから直接ヒアリングに入る

商品が増えた場合、まず商品一覧を見たい場面が増える。直接ヒアリング開始だと、商品把握や任意フィルターができない。

対応: カテゴリカードの遷移先を商品一覧画面に変更し、ヒアリング開始ボタンを一覧画面右上に置く。

### 6. 英語タグが接客中に読みにくい

内部タグは管理しやすいが、売場では「quick-dry」「low-temperature」よりも、お客様の発話に近い日本語の方が速く判断できる。

対応: `categoryFilterProfiles` を追加し、画面表示は日本語の接客フィルターにする。内部では既存タグや価格帯へ変換する。

### 7. イヤホン調査データの確度差

指定イヤホン22件のうち、多くはメーカー公式ページで仕様確認できる。一方で Soundcore Liberty 5 Pro、Soundcore C50i、Soundcore Liberty Buds は日本公式の商品ページや正式JANを確認できない情報が含まれる。

対応: アプリには接客メモとして使える最低限の候補を追加し、`caution` と `research/earphone-products.md` に確認中であることを明記する。実運用前にJAN、正式型番、取扱可否を確認する。

### 8. イヤホン一覧のiPad表示

イヤホンは商品数が22件になり、一覧カードが増える。タグをすべて表示するとカードが長くなり、iPad縦向きで見通しが悪くなる。

対応: 既存方針どおり英語タグは非表示にし、日本語の「接客で使いやすい切り口」を最大6件だけチップ表示する。商品カードは `xl:grid-cols-2` のままにし、iPadでは自然に1列表示できる。

### 9. スマートウォッチの型番コードと色名の確度

Fitbit系の `FB424BKYWFBCJK`、`FB523RGRWFRCJK`、`FB521GLBMFRCJK` は、商品コードとしては扱えるが、JANとしては確認できない。色名も公式Google Storeの色展開とコードからの推定を含む。

対応: `modelNumber` に指定コードを残し、JANは `JAN未確認-...` とする。`research/smartwatch-products.md` と商品 `caution` に、実運用前の型番、色、JAN確認を明記する。

### 10. 健康機能の説明リスク

スマートウォッチは心拍、SpO2、心電図、ストレス、睡眠呼吸など健康寄りの機能が多く、医療的な断定に見えやすい。

対応: 商品トークでは「体調傾向」「参考」「見える化」という表現に寄せ、Sense 2 など上位健康機能の商品には医療診断ではない旨を `caution` に入れる。

### 11. プリンター調査データの確度差

指定プリンター26件はメーカー公式情報を中心に整理したが、Canonの個別製品URLは現時点のURL候補から安定して取得できなかった。また `MFCJ711CDW` は公式上の `MFC-J7100CDW` を指している可能性が高い。

対応: アプリには検索できるよう指定型番を `modelNumber` に残し、`research/printer-products.md` と商品 `caution` に正式型番、JAN、色、販売仕様の確認が必要なことを明記する。

### 12. プリンター一覧のiPad表示

プリンターは26件あり、家庭用、写真用、エコタンク、ビジネスFAX/A3機が混在する。タグをすべて見せるとカードが長くなり、iPad縦向きで一覧性が落ちる。

対応: 既存の商品一覧カードと同様に英語タグは出さず、「写真をきれいに印刷したい」「インク代を抑えたい」「A3も印刷したい」などの接客チップを最大6件に制限する。

### 13. 店舗在庫ドライヤーの型番確度

指定ドライヤー49件は、ハイフンなしの店舗型番で渡されている。メーカー公式ページで確認しやすい型番と、商品マスター確認が必要な型番が混在する。

対応: `modelNumber` に指定型番とメーカー表記型番を併記し、JANは全件 `JAN未確認-...` に統一する。`research/dryer-products.md` に正式商品名、色、JAN確認が必要な型番を残し、アプリ上の `caution` にも実運用前確認を入れる。
